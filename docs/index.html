The first finding

Bikes ride into Manhattan, and stay there

Morning commuters pick up bikes near home and dock them near work. By midday, the residential stations are drained, and they stay empty until people ride home.

Design decisions

Every choice has a reason

The part interviewers ask about. Each one came from a real problem in the data.

Rerunning a load

Idempotent by design

A composite key (station_id, last_reported) plus on conflict do nothing. My second test run inserted exactly 0 rows.

Fake 1970 timestamps

Fix the cause

54 stations reported Jan 2, 1970. The real reason was is_installed = false, so that is what the filter checks.

Mixed ID formats

Keys as text

The same feed sends UUIDs and long numbers. A strict type would have crashed on one of them.

Names vs live counts

Facts and dimensions

Status changes every minute, so it appends. Names and capacity rarely change, so they upsert, one row per station.

Snapshots, not durations

Window functions

LEAD() finds each station's next report, which turns "had 0 bikes at 11:40" into "was empty for 28 minutes".

1,700 rows a minute

Duplicate ≠ redundant

Stations send heartbeats even when nothing changed. No duplicates, but lots of waste. Storing only real changes is the next stop.
